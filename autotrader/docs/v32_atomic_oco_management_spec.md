# v32-1 원자적 주문·보호주문 감시 및 통합 포지션 관리 설계
- 구현 범위: 거래소 OCO 동일 ID 수정이라는 기존 안전 메커니즘을 변경하지 않고, 영속 감축 주문과 실제 거래소 두 차례 조회가 모두 일치하는 **최대 90초** 과잉보호 구간만 `RESIZE_IN_PROGRESS` 로 관측한다.
- 전제: 현재 CORE 부분감축은 `amend-algos cxlOnFail=False` 로 기존 보호주문을 취소 없이 수정한다. OKX API가 주문 수정과 체결을 원자적으로 묶어주는 것은 아니므로 **전체 트랜잭션 원자성은 주장하지 않는다**.
- 불변조건: 거래소 SL/TP 강제 제거 금지, SL 완화 금지, 리스크 증가 신규주문은 기존 게이트 유지, 수량 부족·OCO ID 교체·가격 불일치·90초 초과·원장 누락은 반드시 기존 `MISMATCH_CONFIRMED` 긴급 경보 유지.
- 회복: 기존 `_reconcile_pending_core_reduce` 경로가 영속 주문을 기반으로 재조회하며, 계좌 공통 주문락 하에서 원래 OCO 동일 ID를 읽는다. 본 릴리스는 보호주문이나 주문 크기를 직접 변경하지 않는다.
- 후속 통합 의사결정 우선순위 **설계만**: (1) 거래소 보호 및 긴급 손실청산, (2) 미해결 체결/OCO 재조정 완료, (3) 수익보전 STOP 상향, (4) MFE/부분익절, (5) AI 재검토/추가진입, (6) 대기. 위 우선순위를 LIVE로 재구성하기 전 체결-원장-보호주문 통합 시나리오 재생이 필수다.
- 유의사항: 보호주문이 현재 잔량보다 큰 상태는 실제 포지션에 대한 보호가 없는 상태는 아니지만, 트리거·재진입 시 잠재적 위험은 존재한다. 경보는 **없애지 않고** 경과시간 및 소유권 확인 결과를 명시한다.
- 롤백: 이전 운영 배포 v30 보전, 자동 보호주문 삭제/청산 없음.
